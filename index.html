01
Index

Run analyze in your project root

Open a terminal at the root of your repository. One command does everything: parses every file, resolves imports across files, builds the call graph, runs community detection, traces execution flows, and writes the index to a local .gitnexus folder.

~/projects/your-repo — zsh Copy
$ npx gitnexus analyze
# for non-git folders
$ npx gitnexus analyze --skip-git
walking file tree
parsing with tree-sitter
resolving imports + heritage
running community detection
tracing execution flows
building hybrid search index
✓ indexed · skills installed · AGENTS.md created

After this finishes you will see a few new files in your project. There is an AGENTS.md, a CLAUDE.md, and a folder at .claude/skills with four agent skills inside.

Exploring

Navigate unfamiliar code using the knowledge graph instead of grep.

Debugging

Trace bugs through call chains with full upstream and downstream context.

02
Agents

Edit AGENTS.md to match your stack

The generated AGENTS.md tells every agent how to use the index. Open it and add any project-specific context: language conventions, module boundaries, forbidden patterns, or deployment constraints. Agents read this file automatically on every task.

~/projects/your-repo — zsh Copy
$ code AGENTS.md
# or open with any editor
$ vim AGENTS.md
Context aware

Agents know your module structure before touching a single file.

Conventions

Encode naming rules, patterns to avoid, and preferred libraries.

03
Config

Configure OpenCode to use the MCP server

Add the GitNexus MCP server to your opencode.json. This exposes the knowledge graph through a local socket so OpenCode can query call graphs, resolve symbols, and trace execution paths without leaving your machine.

opencode.json Copy 
{
  "mcpServers": {
    "gitnexus": {
      "command": "npx",
      "args": ["gitnexus", "mcp"]
    }
  }
}
Local socket

Zero network latency. The MCP server runs as a local process alongside OpenCode.

Tool exposure

Exposes graph-query, symbol-resolve, and call-trace as callable agent tools.

04
GUI

Open the web GUI to explore the graph

GitNexus ships a local web interface for visualising the knowledge graph. Run the command below and open http://localhost:4242 in your browser to see the full call graph, community clusters, and execution traces rendered interactively.

~/projects/your-repo — zsh Copy
$ npx gitnexus gui
→ server listening on http://localhost:4242
Graph view

Zoom into any module and see all callers, callees, and cross-file dependencies.

Communities

Automatically detected clusters reveal the real architecture of your codebase.

05
Run

Run OpenCode inside your project

Start OpenCode from the root of the indexed repository. It will automatically detect AGENTS.md and connect to the running MCP server. Your agent now has full architectural context on every message.

~/projects/your-repo — zsh Copy
$ opencode
→ detected AGENTS.md · loading gitnexus skills
→ MCP server connected · graph ready
Auto-detect

OpenCode reads AGENTS.md and activates graph skills automatically.

Zero config

No flags needed. If the MCP server is running and the index exists, it just works.

06
Reindex

Reindex on change

The index does not update automatically. After large refactors, branch switches, or dependency upgrades, re-run analyze to keep the graph accurate. For day-to-day work the existing index stays valid across minor edits.

~/projects/your-repo — zsh Copy
# after a big refactor or branch switch
$ npx gitnexus analyze
# watch mode (re-runs on file save)
$ npx gitnexus analyze --watch
Watch mode

The --watch flag re-indexes automatically whenever files change on disk.

Incremental

Only changed files are re-parsed; large repos reindex in seconds, not minutes.
